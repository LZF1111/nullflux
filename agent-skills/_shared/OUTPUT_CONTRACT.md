# 输出契约 (OUTPUT CONTRACT) — 所有仿真 skill 必须遵守

> 本文件被 openfoam / mfix / lbm / lammps 四个 skill 共同引用。任何算例生成任务的产物都必须满足这里的硬约束。

## 核心原则

1. **只生成完整代码文件，不要求真实运行**。skill 的职责是产出一整套**可交付、可自查、能被人或求解器直接使用**
   的文件；是否在本机跑通由用户/求解器背板负责。
2. **输出整体算例**：不允许只给片段。一次交付 = 该框架跑一个算例**所需的全部文件**（缺一个字典/输入段都算不合格）。
3. **参考官方源码背板写入**：涉及算法代码植入（自定义模型/求解器/kernel）时，必须先定位官方源码里的
   参考实现（见各 skill 的 `backplane/SOURCE_MAP.md`），照其类结构/宏/接口写，禁止凭记忆杜撰 API。
4. **三份总览文档随算例一起输出**（见下），让不运行也能审阅质量、理解算法、预判问题。

## 每次交付必须包含的结构

```
<case_name>/
├── <框架要求的全部算例文件>        ← 完整，不缺项（见各 skill 的"完整文件清单"）
├── MANIFEST.md                     ← ① 代码文件总览
├── ALGORITHM.md                    ← ② 算法总览
└── TUNING.md                       ← ③ 可能问题及调优方向
```

若任务是**算法代码植入**（新增模型/求解器/kernel），额外产出：

```
<model_or_solver>/
├── <源码文件: .H/.C 或 .f90 或 .py/.cpp/.cu ...>   ← 完整可编译文件
├── <编译脚手架: Make/files+options 或 CMakeLists.txt 或 setup>
├── MANIFEST.md      ← 文件总览（每个文件职责 + 依赖 + 编译顺序）
├── ALGORITHM.md     ← 算法总览（公式→代码映射 + 参考的官方源码路径）
└── TUNING.md        ← 可能问题及调优
```
