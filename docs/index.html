功能

它现在能做的事。

以下都对应仓库里的代码，可以直接阅读和修改。

01

对话驱动仿真

描述目标或上传论文，智能体读文献、生成几何与网格、写字典、启动求解、读日志、出图。每一步都是可见的工具调用，可随时打断或插话。

02

后台长时求解

求解作业独立于网页和智能体进程运行；服务重启后自动重新接管仍在跑的作业。作业结束、发散或停滞时唤醒智能体继续。

03

断线自动恢复

模型接口出错时按退避重试，长任务超过重试次数后转为定时保活，接口恢复就从中断处继续。

04

复现偏离审批

论文参数写入锁定文件；几何、边界条件或数值设置上的任何简化都要登记为偏离，由用户在卡片上批准或驳回后才生效。

05

KPI 可信度检查

报告前检查统计时间窗是否越过准稳态、窗长是否足够、哪些指标仍由初值主导；未通过不能宣布任务完成。

06

启动前体检

启动求解前检查网格质量、patch 对应、核数是否超订、时间步设置等常见问题。

07

监控与后处理

作业面板、残差曲线、日志尾部；场切片与时均统计；网页内 STL / 网格 3D 预览；OpenFOAM 字典语法高亮。

08

经验沉淀

验证通过的做法可存成技能卡，报错模式会被记录，供之后的任务检索复用。

09

任意 OpenAI 兼容模型

在设置页填写 Base URL、模型名和 Key 即可，云端 API 或本地 vLLM / Ollama 均可。效果与模型能力强相关。

现状与限制

在研项目，如实说明。

已在用
OpenFOAM 多相流算例（双流体、反应流化床、搅拌槽 MRF、鼓泡塔）的建模、长时求解托管、监控和后处理；MFIX、LBM、LIGGGHTS/LAMMPS 有基础支持。
还没做到
还没有一篇论文被完整端到端复现。长任务中的卡顿主要来自模型接口断线或欠费、等待用户审批，以及模型写出格式错误的脚本；已有自动恢复，但仍需要人照看。弱模型容易在网格和边界条件上出错，审批流程能拦下，但不会替它修好。界面和提示以中文为主。
安装

一行命令。

需要 Node.js 18+ 和 git。求解器装在同一台机器上即可。

~
# Linux / macOS / WSL
curl -fsSL https://raw.githubusercontent.com/LZF1111/nullflux\
/main/install.sh | bash
cd ~/cfdriver && ./start.sh

# 或从源码
git clone --depth 1 https://github.com/LZF1111/nullflux.git cfdriver
cd cfdriver && npm install && npm start

# Windows：下载后双击 start.bat
# 浏览器打开 http://127.0.0.1:5174/app，在「设置」里填模型接口

常见问题

先看这里。

它和通用编程智能体（Claude Code、Codex、OpenCode 等）是什么关系？
底层同样是“模型 + 工具循环”。CFDriver 额外提供了 CFD 专用的工具（求解作业托管、网格与日志检查、后处理）、长时任务的恢复机制和论文复现的审批流程。在我们自己设计的少量对照任务上看到了优势，但样本还小，不作一般性结论。
必须装 OpenFOAM 吗？
要真正跑算例，需要在同一台机器上装好对应求解器（OpenFOAM v2306 / OpenFOAM-10、MFIX 等），CFDriver 会自动查找。只试用对话和后处理可以先不装。
Windows 能用吗？
界面和服务可以直接在 Windows 上运行（双击 start.bat）；OpenFOAM 等求解器通常需要 Linux 或 WSL2。
数据会被上传吗？
算例、几何和结果都留在运行 CFDriver 的机器上。对话内容会发送给你配置的模型接口；使用本地模型则不出本机。
论文复现做到了什么程度？
Lu et al. 2016 中试 MTO 三维反应器正在复现中：冷态 + 热态按原始设置测得约需 3 个月墙钟，提速方案正在对照测试、待审批。CFDriver4MTO 案例页列出了已对上和没对上的指标。
